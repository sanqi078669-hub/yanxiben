# FIX-09 查询性能验收

日期：2026-10-23。Windows，Node v24.19.0，Intel i9-13900HX。

基准使用独立合成数据库，同一数据与最终 schema/索引，对照提交 `f3b721e` 的原服务算法与本次优化算法。测量单进程热缓存服务函数，包含返回对象构造，不包含 HTTP、图片下载和浏览器渲染；不能与历史 HTTP P95 直接比较。先执行旧算法后执行新算法，未进行跨机器或长期负载测试。

复现：`node --import tsx scripts/benchmark.ts --records 10000 --samples 30`；更大规模使用 `--records 20000 --samples 10`。报告写入已忽略的 `test-results/benchmark-comparison-<数量>.json`。`benchmark-baseline.ts` 仅用于保留算法对照，不参与生产调用。

## 实现与限制

- 列表筛选、计数、排序及分页下推 SQL，返回摘要而非完整详情。搜索派生文档保留原 Unicode 小写和中文子串语义，`%`、`_` 作为普通字符；标签/错因/知识点使用派生关联表。触发器随编辑更新，级联删除；备份只保留原始业务数据，恢复时自动重建派生内容。
- 队列先筛选、排序并限制每日数量，再 JOIN 详情；查询次数固定为 2。首页复用一次队列，聚合总数，固定为 6。最新评分使用覆盖索引，避免读取大日志正文。
- 迁移 4–6 添加列表、复习、反向关联、版本和 AI 审计所用索引；EXPLAIN 测试确认按类型列表使用组合索引。索引也加速旧算法，因此这里测得的是同 schema 上的算法差异。
- 统计按区间只选所需字段，用 SQLite iterator 流式计算重复错因和连续次数，不加载答案及整段日志 JSON。仍需遍历符合条件的日志，20 万日志接近 1 秒，不能声称已达到恒定耗时。
- 中文子串搜索仍扫描该用户的搜索文档；相关预览的词法评分仍遍历同科目候选。未引入 FTS 或向量索引，不能据此宣称支持无限数据增长。
- 初版搜索/队列实测出现回退，调整派生筛选和覆盖索引后才形成上述结果；失败中间结果保存在本地报告，不计入通过证据。

功能回归：Unicode/中文/字面通配符、组合筛选、稳定翻页、回收站、跨账号隔离、统计口径、编辑/删除后的派生数据同步及备份恢复。完整自动化 133/133 通过，生产构建通过。构建使用临时 DATA_DIR；构建后个人数据库仍为版本 3、迁移前快照仍为 2 份。
