## A：先解决交付和数据阻断项

### FIX-01：建立可回退基线

实施：先核对 `.gitignore`，排除真实数据、密钥、备份、测试产物与构建缓存；检查拟跟踪文件，再初始化本地 Git 并建立基线。若 Git 写入受环境权限限制，记录具体限制。修复工作保持可审查的提交粒度，不删除用户文件。

验收：`git status`、仓库根目录和跟踪列表可核实；数据与密钥不在暂存/跟踪列表；可以通过基线比较修复差异。远端仓库应由用户明确账号、仓库和可见性后再创建或关联；推送后检查实际 CI 结果。**本地基线完成与远端 CI 通过分别记录，不能混为一项成功。**

### FIX-02：收紧恢复输入与附件响应

实施：把恢复视作外部输入，为每张导入表定义行校验，覆盖类型、空值、枚举、长度、范围、JSON 内容结构、跨表关系和归属。重点覆盖 `logs.payload`、`revisions.snapshot`、`idempotency.response`、合并日志、AI 扩展记录、`relations.type`、`reviews.stage/stage_index`，同时检查 stage、stage_index、success_streak 的一致性。格式不合法时返回可定位到表/行的错误，不回显敏感原文。

附件仅允许受支持的 JPEG/PNG/WebP；核对 MIME 与实际文件格式、大小、哈希及解码限制，不能只信数据库字段。附件接口同时执行 MIME 白名单、`nosniff` 和适合独立图片响应的 CSP。站内图片保留正常预览；下载行为使用明确的下载入口和 `Content-Disposition`，避免一刀切下载破坏 `<img>` 使用。

校验及文件暂存先完成，再进入导入提交；失败时回滚数据并清理本次产生的附件，保留原环境不受影响。UI 容错另见 FIX-04，不能用 UI 容错代替导入校验。

验收：构造摘要正确但内容畸形的备份，分别覆盖坏 JSON、错误 JSON 结构、非法阶段/索引、错误关联类型、HTML/SVG MIME、伪装图片、缺失引用和跨归属引用；全部拒绝且不留下半份数据或附件。合法图片恢复后仍可预览，正常备份往返后条数及关键内容一致。

### FIX-03：集中管理 schema 与兼容升级

实施：收集当前分散的建表、补列与索引操作，建立统一有序迁移入口和 `schema_migrations` 记录，启动时先完成迁移再接受业务访问。迁移事务化、失败不记成功，重复启动不重复执行，停止无条件覆盖 `user_version`。已有无迁移记录的数据库按可识别结构建立基线；未知或更新版本应明确拒绝，不能猜测后继续写入。

备份格式版本与数据库迁移版本分开管理。已支持的旧备份经明确的版本转换补齐已知字段默认值，再执行当前完整校验；未知缺列、未知字段或未来版本明确报错，不能泛化成“任何缺列都填空”。若需要更改备份格式，保留旧版读取测试与说明。

验收：新空库、现有 v1 库、历史备份 fixture 均可升级；升级两次结果不变；模拟中途失败不留下半升级状态；旧备份恢复到当前版本后能够读取、编辑、复习和再次导出；未知/未来版本拒绝且原数据不变。演练使用隔离副本，正式升级前备份。

## B：修复用户操作的确定性缺陷

### FIX-04：请求、解析与错误恢复

实施：抽共享请求函数，区分 HTTP 状态、网络错误和非 JSON 响应，保留安全的错误信息及 requestId；设置、恢复、AI、知识点等调用统一接入。对 UI 历史、版本、选项等 JSON 使用带结构校验的解析函数，损坏单条显示明确错误，不能静默伪造成空数据。

补页面错误边界与重试入口。编辑器失败时退出 loading，显示重试/返回，不能把未加载记录当成可保存空表单。根入口仅对 401 显示登录，对网络/服务故障显示对应错误。缺失初始化材料返回明确 `503 NOT_INITIALIZED`；初始化脚本在账号已存在时也补齐缺失的 session-secret，并说明旧会话失效。错误 toast 使用错误状态。

验收：401、404、413、HTML 500、断网、损坏 JSON 和缺失 session-secret 均可理解且可恢复；加载失败不能覆盖原记录；单条坏历史不能使整个页面白屏；正常登录和改密撤销会话行为保持正确。

### FIX-05：答案长度与 pending 恢复

实施：优先保留当前服务端 50,000 字符上限，抽成共享常量，统一服务端 schema、会话恢复 schema 和 textarea 限制。历史草稿超过上限时允许用户查看、复制、缩短，不能因解析拒绝而静默丢弃。

对明确未提交的校验错误解除 pending 并保留答案供修改；网络超时或结果未知时保留原 body 与幂等键供安全重试。提供继续编辑/放弃待提交状态入口，说明放弃本地重试不会撤销可能已提交的服务端记录；结果不确定时先核对/重试同一请求，不能换新键重复记复习。

验收：上限内/边界/超限答案；400 后可编辑；断网后重试不重复；刷新后能恢复；旧超限草稿不丢失；放弃待提交状态后能继续且不会重复改变计划。

### FIX-06：服务端提示记录与阶段恢复

说明：现有服务端已禁止 `hintUsed=true` 配合 EASY。真正缺口是服务端无法识别用过提示却上报 false 的请求。

实施：提示调用携带已授权的复习项及会话/计划版本，成功提供提示时由服务端记录；提交按对应复习范围的服务端记录与用户声明合并判断。记录生命周期需覆盖刷新、重试和主动练习，不能让过去一次提示永久锁定未来复习，也不能影响纯手工勾选提示。客户端限制保留为交互提示。

暂停时保留原阶段，恢复时还原；历史暂停数据缺少原阶段时按现有调度规则推导，统一单项、批量和撤销逻辑，避免三处规则漂移。新增字段通过 FIX-03 迁移并处理备份兼容。

验收：请求提示后直接构造 `hintUsed=false, rating=EASY` 仍被正确约束；新一轮复习不会被旧记录误伤；提示失败处理口径明确；跨归属请求拒绝；MAINTENANCE 暂停/恢复、批量暂停/撤销以及 NEW/LEARNING 路径均正确。

## C：保证生产可用和规模可用

### FIX-07：恢复工作区生命周期

实施：将恢复 worker 编译为普通 Node 可执行 JS，生产启动不依赖 devDependency `tsx`；Next 启动路径通过模块解析获得。任务有超时、取消、失败状态和日志上限；工作区可删除，有明确保留期限与清理机制，运行中实例不能被误删。处理主服务重启后的工作区状态，停止进程前验证身份，不能仅凭旧 PID 杀进程。端口冲突应可恢复。

验收：在干净目录 `npm ci --omit=dev`、具备构建产物的生产安装中可校验、启动和停止恢复实例；超时、端口占用、主服务重启和删除清理均有结果；失败无孤儿进程和无限增长文件；原站点数据不变。

### FIX-08：读取流时限制体积

实施：保留 Content-Length 快速拒绝，同时在实际消费请求体时累计字节，超限停止读取并返回 413。JSON、图片和恢复 ZIP 采用各自明确上限；大备份使用有界流式落盘/解析，避免先 `formData()` 全量缓冲再检查。所有取消/失败路径清理临时文件。

验收：缺少 Content-Length、chunked、多段表单、伪造小长度和中途断开请求均不能绕过实际读取上限；合法临界大小请求成功，超限及时拒绝且不残留临时文件。

### FIX-09：查询性能

实施：列表过滤、排序和分页下推 SQL，响应只返回列表所需字段；队列一次 JOIN 消除 N+1，dashboard 复用结果并用聚合计数。按实际查询补组合索引及 `revisions(entry_id,created_at)`、`relations(to_id)`、`ai_audit(owner,created_at)` 等索引，先看查询计划避免盲目加索引。

搜索先保证原有中文、标签和大小写语义；SQL LIKE 的通配符须按约定转义，参数化查询不变。仅在基准证明需要时引入 FTS，相关预览仍保留候选上限。统计选择必要列并聚合可聚合内容。

验收：筛选、排序、翻页、删除和跨归属隔离结果与原行为一致；固定数据比较前后 P50/P95、查询数量、响应体积和查询计划。复用 1 万题/10 万日志基准，另测更大数据增长趋势，区分服务函数与 HTTP 耗时。新基准应优于旧实测且无功能回退，不以线性外推冒充实测。

### FIX-10：AI 配置边界

实施：开放有上限的 `maxOutputTokens` 或按 action 设置预算，保留原默认值，按模型能力校验；截断返回明确错误和费用记录，不把不完整结构写入业务数据，也不自动无限重试产生费用。

官方供应商使用已知目标；自定义地址拒绝本机、私网、链路本地及其他非公网目标，检查 IPv4/IPv6、DNS 解析和重定向策略，避免仅靠 URL 字符串判断。若以后支持本机模型，应作为独立、明确授权的连接模式设计。

密钥优先使用部署环境提供的独立秘密；本地模式将加密主密钥移出应用数据与备份目录，评估 Windows DPAPI 是否适合当前单机运行方式。必须设计现有密文迁移、恢复后重新配置和主密钥丢失提示，不能移动文件后导致全部密钥不可读。

增加可配置每日调用限制；费用上限只在价格可计算时执行并明确其为估算，对未知价格不能宣称受费用上限保护。并发请求采用原子预算检查。

验收：DeepSeek 长输出、截断、限流、无价格和预算边界；配置迁移前后密钥可用且接口/日志/备份不泄露密钥；私网 IPv4/IPv6 和 DNS 指向私网等目标拒绝。其他供应商继续只记协议测试，不能写成真实联调通过。

## D：维护性、门禁和交付收尾

### FIX-11：API 与页面拆分

实施：先抽鉴权、CSRF、JSON 读取、错误响应和幂等公共逻辑，再按资源拆处理器或真实路由；保持既有 URL 和契约，避免为缩短文件破坏安全检查。前端按页面动态加载或迁入真实路由；将请求层、基础 UI 与 Markdown 渲染分离，登录页不引入公式和编辑器依赖。

验收：路由回归覆盖各 HTTP 方法、401、CSRF、对象级授权和幂等冲突；登录、今日、详情、编辑、复习等可直接打开/刷新；构建产物与浏览器网络证明页面分包生效，登录页未加载 Markdown/KaTeX 重依赖。

### FIX-12：质量门禁与格式

实施：按当前 Next/React 版本配置 ESLint 和 hooks 规则；添加 Prettier 配置、检查脚本，整理压缩单行代码并移除确认无用的变量。增加有明确覆盖范围的覆盖率报告与基线，优先补迁移、恢复、路由异常及复习状态测试；阈值以实际覆盖数据建立，不能为通过而排除核心文件。

CI 执行安装、lint、format、typecheck、test、build 和生产依赖高危漏洞检查；各项失败可定位，避免只写脚本而不运行。KaTeX override 先核实升级原因与漏洞约束，补公式渲染回归，不直接降级到可能有已知问题的版本。

验收：以上本地检查全部通过；公式覆盖行内、块级、复杂表达式和非法输入。远端 CI 的成功必须附实际运行证据，未推送则标未验证。依赖审计失败列出真实影响和处置，不能静默忽略。
