## 浏览器人工走查

通过真实界面完成：

1. 从本地凭据文件读取账号并登录。
2. 新建带数学公式、正确解法与总结的数学示例。
3. 添加错因与一句话总结，等待约 1.5 秒自动保存，观察“已保存”状态。
4. 重启为生产构建后重新打开，确认记录仍存在、内容版本为 2，公式正常显示。
5. 加入复习计划，打开复习页，确认初始只有题面，没有解析。
6. 填写独立作答、展开解析、评价并提交，显示“这次练习已经保存”。
7. 返回今日学习，核对待复习 0、累计收集 1、今日已练习 1。

浏览器记录标题为“【示例】等价无穷小：先看运算结构”，来源与作答都标注为本地验证内容。首页截图见 `screenshots/today.png`。

## 本轮自测发现与修复

新增回归测试覆盖以下八项，全部通过：

| 问题 | 修复后的行为 |
| --- | --- |
| 跳过前面的题，完成末题可能提前结束 | 仅移除已提交题目，继续未完成题，不重复已完成题 |
| 408 Markdown 导出缺少选项 | 保留题型与完整选项 |
| 关联长难句删除后，生词无法编辑 | 保留既有引用并允许保存，界面标记引用不可用；拒绝新增无效关联 |
| 非生词类型可混入语境数据 | 服务端拒绝不兼容字段 |
| 对未删除记录执行恢复会暂停计划 | 返回冲突，不修改现有计划 |
| 重复删除增加版本和历史 | 重复删除不产生额外内容变更 |
| 标签搜索大小写、空白规则不一致 | 搜索与保存统一归一化 |
| 分页接受小数或无限大等异常参数 | 严格校验正整数与范围 |

另外改进了异步请求过期响应保护、空白新建页的离开判断、标签尾逗号处理、首次保存期间禁用编辑、复习加载失败重试，以及计划冲突时保留作答并转为主动练习。后者已通过构建和类型检查，尚未完成双标签页的浏览器冲突走查。

### 功能合理性结论

“快速收集—后续整理—主动加入复习”的分步流程合理，适合先记录再分析；主动练习不改计划、使用提示限制最高评分、恢复记录后暂停计划等规则已通过测试。本地核心流程可以试用，但不能认定原需求已全部完成：大型资料库的关联选择与生词查重仅覆盖最近 100 条，搜索仍为应用层筛选，导出为同步任务，完整差异见 ADR。

### 数据规模基准

通过 `node --import tsx scripts/benchmark.ts` 在独立临时数据库生成 10,000 条记录、100,000 条历史、20,000 个标签。环境为 i9-13900HX、Node 24.19、Windows；每项 30 次热缓存采样。

| 服务层操作 | P50 | P95 | 最大耗时 |
| --- | --- | --- | --- |
| 列表 | 178.70 ms | 188.39 ms | 200.15 ms |
| 搜索 | 194.65 ms | 200.67 ms | 201.21 ms |
| 复习队列 | 106.87 ms | 111.21 ms | 112.22 ms |

增加了复习历史查询索引。以上是单进程服务层基准，不包含 HTTP、页面渲染、图片或并发压力，不能据此认定全部性能要求达标。原始结果保存于本地 `test-results/benchmark.json`。
