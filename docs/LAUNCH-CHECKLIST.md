整理日期：2026-10-24。适用范围：5–7 位受邀用户，各自使用独立账号和私人题库，通过公网 HTTPS 访问。

## 一、上线前必须完成

### 01. 确定使用范围

- [x] 明确各账号默认互不可见；如果需要共享题库，单独定义共享权限和编辑冲突规则。
- [x] 确定负责发布、备份、账号恢复和故障处理的人。（用户本人；agent 辅助，不替代持续告警接收。）
- [x] 确认访问方式：公网 HTTPS；如果改为局域网或受控私网，更新本清单与验收范围。

验收：写明账号数量、数据可见范围、访问地址和维护负责人。

### 02. 开通与维护独立账号

- [ ] 为实际使用者分别创建账号，私下交付初始密码，首次使用后修改密码。
- [x] 整理管理员创建账号、重置遗忘密码、停用账号和撤销会话的受控操作步骤，补齐缺少的能力。（accounts CLI，本次合成 HTTP 验收。）
- [x] 明确初始凭据文件的保存与清理方式，避免后创建账号覆盖凭据文件后无法追溯交付情况。（credentials/随机UUID.txt，独占写入，私下交付后逐文件清理。）

当前基础：`scripts/init.ts` 可按 `INIT_USERNAME` 创建不同账号，已有账号不会改密；没有注册页面。每次创建会写同一个 `local-login.txt`。小范围邀请使用可以由管理员开通，不要求增加公开注册或完整后台。

验收：所有实际账号可登录；A 账号不能读取、修改或导出 B 的记录、附件、设置及恢复空间；密码重置和停用流程可执行。

### 03. 部署生产服务与持久存储

- [ ] 准备持续运行的服务器，固定 Node.js、npm 和发布版本，使用生产构建运行。
- [ ] 配置固定的私有数据目录、附件目录和独立 AI 主密钥路径；发布代码时保留这些目录。
- [ ] 配置开机启动、进程异常重启、日志保存和服务停止步骤。
- [x] 明确先采用单机、单应用实例；SQLite 数据文件位于该机持久磁盘。（方案已确定，实际磁盘待部署。）

验收：应用进程重启、服务器重启和替换代码后，账号、笔记、图片、复习进度与 AI 配置仍可读取；交付包不包含私人数据或密钥。

### 04. 配置 HTTPS 访问入口

- [ ] 配置正式访问地址、TLS 证书、证书续期与反向代理。
- [ ] 代理转发到本机应用端口；只开放需要的入口，不暴露数据目录与临时恢复服务端口。
- [ ] 生产 HTTPS 下设置 `SECURE_COOKIES=1`，核对登录、退出、Origin 同源检查和真实客户端 IP 的可信来源。
- [ ] 设置兼容现有上传、AI、导出与恢复请求的代理大小限制和超时。

当前基础：`npm run start` 监听 `127.0.0.1`，可由同机反向代理接入；跨设备和 HTTPS 尚未验收。

验收：实际电脑与手机可通过正式 HTTPS 地址登录、保存和上传；长请求不会因代理配置提前失败；浏览器 Cookie 的 Secure 属性正确。

### 05. 完成公网安全配置

- [ ] 在保留账号登录限流的基础上，补充 IP 与全局限流，正确处理代理后的客户端 IP，避免任意用户名绕过账号限流。
- [ ] 实施并验收全站 CSP；按既有审查计划处理 nonce，验证页面脚本、公式、图片和下载兼容性。
- [ ] 在实际服务器操作系统核验数据、数据库、附件、备份和密钥目录权限。
- [ ] 核对正式配置与发布目录，确保凭据、日志、数据库和备份不能被静态访问。

验收：重复失败登录和超额请求被限制；跨账号访问被拒绝；CSP 生效且正常流程可用；实际文件权限检查通过。

### 06. 处理网页恢复的远程访问问题

- [x] 选择并实现上线后的恢复方式：管理员受控恢复，或设计带鉴权的 HTTPS 恢复入口。（RESTORE_MODE=admin，本次浏览器已核对提示。）
- [x] 如果暂用管理员恢复，应调整网页入口和提示，避免用户启动一个无法远程访问的临时服务。（运行时策略返回，服务端禁止恢复空间路由。）
- [ ] 若保留用户启动恢复空间，补齐全局资源限制、HTTPS 路由、隔离鉴权、停止与清理机制。

当前缺口：恢复模块启动 `127.0.0.1` 临时服务并返回本机地址；远程用户访问该地址时访问的是自己的设备。原有本机恢复验收不能覆盖这一场景。

验收：用户或管理员能够按正式流程恢复并核对数据；不会得到不可用的本机链接，也不会暴露无保护的临时端口。

### 07. 建立适用于多账号的自动备份

- [ ] 实现或配置多账号实例备份，覆盖全部账号、数据库与匹配附件，明确认证数据和运行配置的恢复方式。
- [ ] 采用一致性快照或短暂停写方案，避免直接复制运行中的 SQLite 主文件而漏掉 WAL 数据。
- [ ] 配置定时任务、加密异地存储、保留规则与失败通知；可按项目初始目标保留最近 7 份日备份、4 份周备份。
- [ ] 独立安全保管 AI 主密钥、必要配置和恢复说明，并控制访问权限。

当前缺口：网页导出是单用户备份；`scripts/data.ts` 的 CLI 备份明确拒绝账号数不等于 1 的实例。开通多个账号后不能直接沿用现有 CLI 定时备份。学习 ZIP 不包含账号认证和 AI 密钥，且 ZIP 为明文。

验收：自动任务实际生成全部账号可恢复的数据，附件匹配；备份存于不同故障位置且加密；任务失败能被维护人获知。

### 08. 完成正式数据迁移与恢复演练

- [x] 决定正式环境使用全新数据，还是迁移现有个人数据。（用户确认全新数据；个人主库不迁移。）
- [ ] 若迁移现有数据，先做有效备份，在副本演练后执行正式迁移，并保留回退材料。
- [x] 在隔离环境恢复多账号备份，检查账号、记录、图片、关联、计划、历史和 AI 配置恢复方式。（本机合成快照启动通过，异地仓库恢复仍待验收。）
- [ ] 记录恢复耗时与可接受的数据损失；项目初始目标为最多丢失 24 小时数据、4 小时内恢复，需用实测确认。

当前记录：个人 v3 数据库副本升级到 v9 已演练；历史报告中的源库仍为 v3，正式迁移状态需在发布时重新核验。

验收：所有实际账号的恢复数量与关键业务抽样一致；能按记录的步骤回到可用版本。

### 09. 确定容量限制与资源告警

- [ ] 明确每账号可用容量、实例总容量及超限处理，给数据库、图片、历史版本、导出缓存和多代备份预留空间。
- [ ] 配置磁盘余量、服务不可用、连续错误和备份失败告警。

验收：用户知道当前可用范围；磁盘不足或备份接近上限能提前发现。现有功能不应宣称已支持原设计的 5 GB 附件目标。

## 六、P0/P1 修复与 QA-001 候选准备

以下是已完成本地修复的摘要，不是候选提交或 Linux 部署验收：

- SEC-001：异步校验后在最终事务重新核对密码哈希、会话和账号状态，条件更新并撤销其他会话与恢复授权；异常影响行数注入仍为遗留。
- SEC-002：设置新密码统一按 UTF-8 最多 72 字节，保留至少 12 位要求；登录及当前密码验证兼容存量长密码，超限新密码拒绝且界面提示字节计数。
- REL-001：账号 64 MiB/12 文件、实例 192 MiB/60 文件；每账号 5 分钟最多 3 次新任务。对应 EXPORT*CACHE*\* 配置及 5 GiB 空闲预留、60 秒清理周期见部署手册。生成前预留、落盘前复核，失败释放；有效旧键 7 天可重放且不计频率，不静默淘汰；启动独立定时清理。真实体积校准仍待完成。
- REL-002：合并事务内先计算预计增量，再提交前检查实际总量；合并/撤销超限整体回滚。批量改标签逐条事务按已提交数据及本条修改后的总量检查，超限条目回滚，先前成功项保留，成功回执与记录/历史/派生数据一致。
- REL-003：附件上限 10 MiB，使用共享层 180 秒总时长；处理 timeout/abort，卸载取消并单次结算。P1 本机 Edge 已验证停滞、中断、取消及离开页面后的文字/草稿保留；原生超时在测试中加速触发，未做真实 180 秒大图片弱网吞吐验收。
