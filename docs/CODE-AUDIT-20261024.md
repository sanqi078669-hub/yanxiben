## 5. 详细分析

### SEC-001：在途改密能够覆盖管理员重置

**状态：确定问题，模块级复现成功。**

**位置：**`src/modules/auth/reauth.ts:49`；`src/modules/http/handlers/account.ts:32–38`。

**问题说明与故障路径：**

1. 请求通过入口会话检查，开始验证旧密码。
2. `bcrypt.compare()` 或后续 `bcrypt.hash()` 让出执行权。
3. 管理员重置密码并撤销该账号会话。
4. 原请求继续执行无条件 `UPDATE users SET password=? WHERE id=?`。

最终写入没有比较原密码哈希，也没有重新检查当前会话是否仍存在、账号是否停用。

**影响范围：**需要先拥有有效会话并通过原密码验证；不等同于未认证远程接管。在该前提下，旧请求能够覆盖管理员刚完成的重置，削弱会话撤销和账号维护的安全边界。

**复现证据：**

```json
{
  "requestCompletedAfterSessionRevocation": true,
  "adminResetOverwritten": true,
  "pendingPasswordAccepted": true,
  "remainingSessions": 0
}
```

**修复建议：**

- 二次验证返回所验证的凭据版本或原密码哈希。
- 新哈希计算完成后开启最终事务。
- 在事务中重新检查会话有效性、账号启用状态、密码哈希未变化。
- 使用带旧哈希条件的更新，并检查影响行数。
- 在同一事务中处理其他会话和恢复授权撤销。
- 二次验证本身也应拒绝比较期间已经失效的凭据状态。

**验证方式与相关测试：**在比较和哈希阶段分别插入可控等待，执行管理员重置、停用、撤销，以及第二次改密，确认旧请求失败且不覆盖新状态。补充真实 HTTP 回归；本次复现没有重跑 HTTP 端到端流程。

### REL-001：导出缓存能够持续消耗共享磁盘

**状态：确定代码路径；磁盘耗尽速度未做压力测试。**

**位置：**`src/modules/data-management/exports.ts:12,53–80`；`src/modules/data-management/export-worker.ts:25`；`src/modules/http/handler.ts:48`。

**问题说明：**每个新幂等键生成新 UUID 文件，保留 7 天。过期清理只在下一次导出发生时执行。

- HTTP 配额检查明确排除 `exports`。
- 导出 worker 限制并发数，没有累计文件数或字节预算。
- `checkBackupCapacity()` 限制单个归档，不能限制缓存总量。
- 实例容量计算未包含 `export-cache`。

**触发路径与影响范围：**持有自己账号和密码的用户，通过不断更换幂等键即可积累归档副本。正常重复点击导出也可能造成增长。磁盘压力会波及同机数据库、其他账号和备份。

**修复建议：**

- 为账号和实例设置缓存字节、文件数预算。
- 生成前预留临时空间，落盘前复核可用空间。
- 对新导出设置频率限制；原键重试继续复用回执。
- 定期清理过期缓存，不依赖下一次导出触发。
- 不应静默删除有效期内仍承诺幂等重放的文件；预算不足时拒绝新任务。

**验证方式与相关测试：**配置很小的合成缓存预算，连续提交新键，确认超限返回稳定错误；既有下载可用，其他业务仍可写入。

### SEC-002：网页新密码未遵守 bcrypt 字节边界

**状态：确定问题，局部行为复现成功。**

**位置：**`src/modules/http/handlers/account.ts:28`；对照 `src/modules/auth/admin.ts:25`。

**证据：**网页使用 `z.string().min(12).max(200)`，CLI 已使用 `Buffer.byteLength(password) > 72` 检查，两处行为不一致。两个共享前 72 个 ASCII 字节、仅第 73 字节不同的合成密码，可通过同一个哈希验证。此行为符合 [bcrypt.js 官方说明](https://github.com/dcodeIO/bcrypt.js/)。

**触发条件与影响：**用户设置长密码并仅修改有效范围之外的后缀时，可能认为已经改密，实际旧密码仍然有效。中文和 emoji 更容易触及字节边界。

**修复建议：**对新设置密码统一使用 UTF-8 字节校验，并在界面给出明确提示。兼容处理已有长密码，避免直接限制所有登录输入而使现有用户无法登录。

**验证方式与相关测试：**覆盖 ASCII、中文、emoji 的 72/73 字节边界，以及仅修改超限后缀的改密场景。

### REL-002：批量写入放大突破容量预留

**状态：确定问题，增长量已复现。**

**位置：**`src/modules/data-management/quota.ts:45`；`src/modules/entries/knowledge.ts:145,155,218`；`src/modules/entries/batch.ts:134`。

**问题说明：**知识点合并为受影响记录生成 revision，更新记录及派生数据，并将完整 `before`、`after` 状态存入合并事件。入口只在开始时检查一次容量，并固定预留 2 MiB。

**复现证据：**使用 10 条合法合成数学记录：

| 指标           |          字节 |
| -------------- | ------------: |
| 合并前账号计量 |     6,012,032 |
| 合并后账号计量 |    15,040,417 |
| 单次增长       | **9,028,385** |

复现没有填满磁盘，也没有直接验证越过 80 MiB；但已证明固定预留不能覆盖该操作的合法增量。接近上限时可由此越界。

**影响范围：**批量合并、快照及类似历史放大操作；越界后账号可能进入写入受限状态。

**修复建议：**在合并事务内完成最终容量校验，超限整体回滚。批量改标签应按其现有部分成功语义，在每条事务中检查新增历史容量，并正确生成回执。

**验证方式与相关测试：**构造接近上限的账号，分别执行大范围合并、撤销及批量改标签；验证失败后记录、历史、派生表和回执一致。

### PERF-001：配额检查成为随历史增长的同步热点

**状态：确定结构性开销；实际生产延迟待测。**

**位置：**`src/modules/data-management/quota.ts:11–25`。

**问题说明与证据：**`accountUsage()` 每次重新读取表结构，并对包含 `owner` 的表执行完整行 JSON 序列化计量，包括大字段、修订快照和历史数据。

**触发条件与影响范围：**编辑器自动保存会重复触发此流程。同步 SQLite 与 JSON 计算运行在请求进程中，历史越多，单次保存附加成本越高；索引不能消除对选中行大字段的读取和序列化。

**修复建议：**逐步维护事务内增量计量，表结构元数据至少缓存一次。保留离线全量校准，防止计数漂移，无需引入外部数据库或队列。

**验证方式与相关测试：**比较不同历史规模下的自动保存延迟和事件循环延迟，并检验计量在回滚、删除、合并、恢复后仍一致。

### REL-003：图片上传缺少明确超时和取消生命周期

**状态：确定缺少处理；浏览器故障表现待实测。**

**位置：**`src/components/Editor.tsx:248–272`。

**问题说明与证据：**编辑器上传采用独立 XHR，未使用共享请求层已有的超时机制，仅设置 `onerror`、`onload`。上传连接若保持打开但不再推进，Promise 无法按应用约定结束，`uploading` 状态也无法及时释放。

**影响范围：**弱网、服务端连接停滞、上传中途离开页面等场景下的保存、取消和重试体验。

**修复建议：**设置与上传政策一致的 `xhr.timeout`，处理超时及取消回调；组件卸载时取消请求，并确保 Promise、状态更新只能结算一次。

**验证方式与相关测试：**模拟服务端不返回、上传中断、主动取消及离开页面，确认可恢复操作，错误反馈清楚，未保存文字仍在。

## 6. 安全专项

- **认证与授权：**服务端 sessions 表支持撤销，认证检查账号停用状态；已读业务入口普遍使用 `owner` 条件，现有跨账号测试通过。主要缺陷是 SEC-001 的异步状态转换。
- **输入校验与输出编码：**请求体有实际字节上限，不仅依赖 `Content-Length`；业务使用 Zod。Markdown 未启用任意 HTML 渲染，KaTeX `trust: false`，外部图片被限制。
- **注入类风险：**已审调用链主要使用参数化 SQL；动态标识符来自固定字段或数据库结构。未确认可利用的 SQL 注入。
- **CSRF：**写操作要求自定义请求头，并检查 Origin；正式配置使用固定 `PUBLIC_ORIGIN`。未发现已确认绕过路径。
- **SSRF：**AI 目标限制 HTTPS、公网地址，检查全部 DNS 结果并固定连接 IP，拒绝重定向；相关模拟测试通过。
- **文件安全：**附件使用服务端 UUID 文件名、校验归属、限制图片格式并重新编码；恢复校验路径、清单、摘要、引用和图片内容。
- **敏感信息与密钥管理：**AI 配置使用 AES-GCM，主密钥要求位于数据目录外；公开配置不返回密钥。所读模板未发现真实秘密，未据此声明整个历史无泄漏。
- **依赖与供应链：**本次生产和完整 npm 审计均返回 0 条漏洞记录。此结果不等于不存在未知漏洞，也不覆盖系统软件。
- **日志与错误：**普通未知错误响应不返回堆栈或上游正文；恢复 worker 会输出诊断日志，应继续限制日志访问权限。
- **其他风险：**导出磁盘资源滥用见 REL-001。Windows 私有文件实际 ACL 尚未验证。

## 7. 性能与可靠性专项

- **数据库与缓存：**采用 WAL、外键和事务，列表及队列已有索引与查询下推；配额同步全量计量是本次重点热点。导出缓存缺乏总量治理。
- **并发与异步：**记录更新有版本检查；复习提交有幂等键和同日约束；图片处理和导出有并发限制。密码变更缺少最终状态重验。
- **资源释放：**图片任务通过 `finally` 释放槽位，请求体读取会取消并释放 reader，导出/恢复 worker 有超时及取消处理；编辑器 XHR 是明确缺口。
- **超时、重试、幂等：**共享请求层覆盖响应和正文超时；AI 有超时且不盲目自动重试，避免重复费用。导出同键固定归档是合理设计，应保留。
- **日志、监控与告警：**已提供健康、磁盘和备份新鲜度检查模板，但没有本次 Linux 实机证据。
- **容量与扩展性：**80 MiB 账号及 1 GiB 实例政策具有限制作用，但批量放大和缓存绕过使其不能充当完整容量保证。
- **规模限制：**中文子串搜索、统计及合并仍存在随数据增长的计算；不能从小样本测试推断高并发能力。

## 8. 架构与可维护性

- **模块边界与耦合：**HTTP、认证、AI、数据管理已有目录分层；但通用 `AppError/assert` 位于 entries 服务，多模块反向依赖该业务模块。
- **分层与职责：**部分 HTTP handler 直接执行 SQL，部分通过业务服务完成事务，边界尚不统一。
- **重复代码与抽象：**网页和 CLI 密码策略已经出现分歧，应优先提取共享规则。在线记录校验与备份校验存在必要差异，但模板不变量宜共享。
- **配置管理：**有环境模板和正式部署说明；关键策略通过环境变量开关控制。应对候选发布配置进行实际验收。
- **可读性与复杂度：**TypeScript 严格模式、未使用变量检查及格式门禁有效；数据库行仍大量使用动态类型，运行时 schema 承担重要防线。
- **技术债建议：**优先统一密码与容量契约，再整理错误类型和事务服务边界。现阶段没有证据要求迁移数据库或引入分布式架构。
